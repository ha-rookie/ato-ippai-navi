# JR関西本線（名古屋市内）

## 対応範囲

JR東海・関西本線のうち、あと一杯ナビでは名古屋市内3駅を対象にする。

| 内部destinationCode | 公式駅番号 | 駅名 | 名古屋発の最終到達列車 |
| --- | --- | --- | --- |
| JR-CJ00 | CJ00 | 名古屋 | 徒歩帰宅 |
| JR-CJ01 | CJ01 | 八田 | 23:57 普通 四日市行 |
| JR-CJ02 | CJ02 | 春田 | 23:57 普通 四日市行 |

蟹江以西は名古屋市外のため本MVP対象外。

## 判定方式

既存の `nagoya` 徒歩hubを再利用する。

1. 現在地から名古屋駅までGoogle Routes APIのWALKで所要時間を取得
2. 駅バッファと最低乗車余裕を加算
3. 内部JSONの23:57境界と比較
4. 間に合わない場合はタクシーフォールバックを比較

TRANSIT APIや全時刻表はランタイムに保持しない。

## 公式一次情報

JR東海 2026年3月14日ダイヤの名古屋駅「関西線 四日市・松阪方面」公式PDFをCIで取得する。

https://railway.jr-central.co.jp/time-schedule/srch/_pdf/data/202603/kansai_Nagoya_B_wh_d.pdf

現行PDFでは平日・土曜休日とも23時台は 11 / 25 / 40 / 57 分発で、最終は23:57 四日市行 普通。0時台は時刻欄が空。

停車駅案内で普通列車が名古屋・八田・春田に停車することを確認する。

駅番号はJR東海公式路線図で CJ00 名古屋 / CJ01 八田 / CJ02 春田を確認する。

https://global.jr-central.co.jp/en/info/railwaymap/_pdf/railwaymap.pdf

駅番号は公式路線図PDF上で画像要素として描画され、`pdftotext` では安定抽出できないため、CIで虚偽の自動検証は行わない。公式PDFをartifactとして保存し、レビュー済み静的メタデータとして扱う。

## lastArrival

公式の名古屋駅PDFだけでは八田・春田の正確な到着時刻を安全に自動取得できないため、`lastArrival` は `null` とする。

到着時刻を推測して埋めない。

## fail-closed

次のいずれかが変わった場合、公式データCIを失敗させる。

- 23時台の2つの日種別ブロック
- 23:11 / 23:25 / 23:40 / 23:57 の並び
- 最終列車の四日市行 / 普通
- 0時台に実列車が追加された場合
- 停車駅案内の名古屋 → 八田 → 春田の順序
- production JSONと公式生成JSONの不一致

## 名前空間

JR東海の公式駅番号をUIではそのまま表示するが、内部codeには事業者prefixを付ける。

- UI: `CJ01 八田`
- API / JSON / localStorage: `JR-CJ01`

これは近鉄で導入したoperator namespace設計と同じ考え方で、将来の事業者間コード衝突を避ける。
